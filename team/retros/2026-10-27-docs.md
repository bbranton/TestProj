## Themes

### What worked

- **The cross-doc findings table kept five parallel doc PRs consistent.**
  Each `X-` finding named the doc that owed the fix and the PR that made it,
  so no doc PR edited another persona's file. Examples: X-6 (show results as
  they arrive vs. save only a complete Refresh), X-24 (one backend
  instance), X-31 (FR-23 status rules, fixed in
  [#7](https://github.com/bbranton/TestProj/pull/7)). Raised by the project
  manager, requirements engineer, architect, UI/UX designer, test engineer,
  developer, and CFO. Evidence: `canvas-docs-review/cross-doc-findings.md` in
  the project's shared files.
- **Traceability holds.** `trace.py --untested 1` finds no Phase 1
  requirement without a test procedure; it caught NFR-11, NFR-14, and NFR-41
  on [#6](https://github.com/bbranton/TestProj/pull/6), fixed in
  [#9](https://github.com/bbranton/TestProj/pull/9) (X-23). A link and ID
  check finds no broken links and no undefined FR or NFR IDs across the
  seven docs. The token path (NFR-10 to NFR-14) maps onto the design's
  [security table](/docs/canvas-portal/03-design.md#7-security) and has a
  Phase 1 test for each row. Raised by the requirements engineer, test
  engineer, developer, DevOps engineer, and cybersecurity engineer.
- **Big decisions were asked before they were written.** D-1 to D-8 each
  had a recommendation and six were settled on 2026-10-25; GraphQL was
  asked as Q-10 on #6 and landed in the design, roadmap
  ([#27](https://github.com/bbranton/TestProj/pull/27)), and requirements
  in one pass. Raised by the project manager and architect.
- **Fresh reviewer threads were cheap and found real problems.** Doc
  reviewers on #4 and #6 cost $2.00 to $4.93 each
  ([cost log](/team/Management/cost-log.md)), and outside reviews caught
  what owners missed, such as Management M-1 (HTTPS in Phase 4 while the
  test deploy is internet-facing in Phase 1). Raised by the CFO and
  requirements engineer.
- **Screen words moved into one glossary** in
  [#31](https://github.com/bbranton/TestProj/pull/31) for $3.32. Raised
  by the UI/UX designer and CFO.

### What got in the way

- **Requirements moved while the downstream docs were being reviewed.**
  All five doc PRs opened within minutes on 2026-10-25 and were reviewed in
  parallel while #6 moved Phase 1 scope: FR-45 went Phase 3, 2, 1; FR-78
  went 1, 2, 1; course colors moving to Phase 5 took six commits across five
  docs. The UI spec's second day cost $24.93 for six rounds of sketch
  redraws, and #6's second row $22.66 over nine rounds; the CFO puts the
  avoidable share at $25 to $35 of about $130 logged for the six docs. The
  roadmap trailed, needing catch-up PRs #32, #36, #42, and #44, and the
  test plan's change log grew one row of over 60 changes that no longer
  says what changed for each decision. Raised by every persona but the
  developer; the cybersecurity engineer's example is NFR-11, which moved
  phases and was split and rejoined across three change-log rows.
  Suggestions S-1 and S-6.
- **The design, UI spec, and test plan merged with no reviewers.** #4 and
  #6 each had four reviewer threads; #7, #8, and #9 have no GitHub reviews
  and no reviewer rows in the cost log. No one checked the test plan
  against the design's endpoints, the design for buildability, the test
  plan's CI assumptions (Playwright, a Postgres service, CI screenshots,
  none of which the [CI workflow](/.github/workflows/canvas-portal-ci.yml)
  runs yet), or the security design as its own review. Some gaps reached
  the Team Lead's own review instead (`unlock_at` and `lock_at`, FR-23
  status rules). Raised by the architect, test engineer, developer, DevOps
  engineer, and CFO; the UI/UX designer named the gaps that reached the
  Team Lead. Suggestion S-2.
- **The design and UI spec still detail later phases.** The design (858
  lines) has full Phase 3 sections and about 60 later-phase mentions; the
  UI spec (951 lines) has full Phase 5 screens. Every phase move rewrote
  them (orphaned cards went Phase 3, 2, 1 in three design commits), and
  Phase 1 is hard to pull out for building. Raised by the architect, UI/UX
  designer, and developer. Suggestion S-3.
- **Security and deploy gaps don't show in the docs.** All ten rows of the
  [security register](/team/QA/notes/cybersecurity-engineer.md#security-register)
  are open, including output escaping and a Content-Security-Policy
  ([#18](https://github.com/bbranton/TestProj/issues/18)) with no row in the
  design, and token storage ([#46](https://github.com/bbranton/TestProj/issues/46))
  gated before Phase 1 step 2. Two potential data breaches from the
  roadmap review are still open
  ([#25](https://github.com/bbranton/TestProj/issues/25),
  [#26](https://github.com/bbranton/TestProj/issues/26)). No doc says how the portal is deployed,
  rolled back, or backed up, though Phase 1 step 6 puts real tokens on an
  internet-facing server (R-14). Security joined the roadmap and
  requirements reviews late. Raised by the cybersecurity engineer, DevOps
  engineer, and architect. Suggestions S-4 and S-5.
- **Doc records outside the repo went stale.** The cross-doc findings table
  still lists every doc PR as *Open* and X-17 as *Waiting* after Q-11 was
  answered, and the only Phase 1 summary (`phase-1/phase-1-features.md`)
  was written from an unmerged commit of #6. Neither has an owner. Raised by
  the requirements engineer and developer. No suggestion was made.
