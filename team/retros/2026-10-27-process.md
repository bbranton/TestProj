# Process retro, 2026-10-27

The project manager's note from the team retro on how the team works,
following the [`retro` skill](/.claude/skills/retro/SKILL.md). A retro on
the Canvas portal docs ran the same day and has its own note,
`2026-10-27-docs.md`.

## Window and topic

- **Window:** all work to date, from the project's start to 2026-10-27, as
  the Team Lead asked.
- **Topic:** how the team works: skill development, the PR and review
  flow, team communication (coordinator relays, decision requests, daily
  logs, the board), token use and cost, and other process. Doc content is
  left to the docs retro.
- **Took part:** all nine personas: project manager, requirements
  engineer, test engineer, architect, UI/UX designer, developer, DevOps
  engineer, cybersecurity engineer, and CFO. To save cost, one thread per
  persona wrote feedback for both retros. The feedback is in the project's
  shared files under `retros/2026-10-27-process/`, not in the repo.

## Did the last changes help?

This is the team's first retro, so there are no earlier retro changes to
check. The next retro checks the decisions below.

## Themes

### What worked

- **Small PRs with a fresh reviewer thread are cheap.** Most reviewer rows
  on 2026-10-27 cost $0.57 to $1.77, such as the DevOps engineer's peer
  review of [#87](https://github.com/bbranton/TestProj/pull/87) ($0.84)
  and the architect's review of
  [#88](https://github.com/bbranton/TestProj/pull/88) ($0.83), against
  $4.80 for the project manager's review of requirements #6 under the old
  flow. Raised by the architect, CFO, cybersecurity engineer, DevOps
  engineer, project manager, requirements engineer, and UI/UX designer.
  Evidence: `[cost]` notes on the [team board](/team/workspace.md#the-board)
  and the cost log (`/mnt/project-files/costs/cost-log.md`).
- **Separating decisions from merging.** Since
  [#71](https://github.com/bbranton/TestProj/pull/71), the Team Lead
  answers decision requests and owners merge their own PRs, so reviews
  stay small and decisions get a written record. Raised by the project
  manager. Evidence: the project manager's
  daily log (`/mnt/project-files/notes/daily/2026-10-27-project-manager.md`).
- **Reviewers fix their own files on the PR branch.** On #82, #88, #89,
  #91, and #94, the reviewer committed the fix to its own file instead of
  handing it back. The requirements engineer (#82, #94) and test engineer
  (#88) say those reviews closed in one round. Raised by the requirements
  engineer, test engineer, and architect. Evidence:
  requirements engineer's log (`/mnt/project-files/notes/daily/2026-10-27-requirements-engineer.md`),
  test engineer's log (`/mnt/project-files/notes/daily/2026-10-27-test-engineer.md`), and
  the architect's `[cost]` notes for #88, #89, and #91 on the board.
- **The cost log gives real numbers to plan with.** Rows by PR and round
  (26 priced rows, about $150) show that long threads cost most and why:
  cache reads were 78.1M of the roadmap owner thread's $40.89. Raised by
  the project manager and developer. Evidence:
  cost log (`/mnt/project-files/costs/cost-log.md`).
- **One writer for the cost log.** Since threads report rows as board
  notes and only the CFO writes the log
  ([#59](https://github.com/bbranton/TestProj/pull/59)), no PR has
  conflicted on it. Raised by the CFO and DevOps engineer.
- **Scripts beat reading.** `trace-requirement` checks IDs, phases, and
  test coverage in one run, and found real gaps. Raised by the developer
  and test engineer.
- **Early, narrow security input.** On
  [#92](https://github.com/bbranton/TestProj/pull/92) the cybersecurity
  engineer sent four points before the review and the owner folded them
  in, so the review itself found little. Raised by the cybersecurity
  engineer; the DevOps engineer adds that checking the live repo with
  `gh api` on #92 caught what a doc review missed.

### What got in the way

- **Long, reused threads are most of the bill.** Cache reads dominate:
  the #8 owner thread cost $29.14 (59.8M cache-read tokens in one row),
  #6 $22.66, the roadmap thread $40.89, and the reused team thread $14.92
  for #79 to #85 and $11.91 for #86 to #90, against about $1 to $2 for a
  fresh thread per PR. The architect's persona file still says "one
  long-running architect thread". Reuse alone isn't the cause: the
  cybersecurity engineer reused one thread across #88 and #90 and kept
  each review to about a dollar. Cost grows with a thread's length and
  the rounds it carries. Raised by seven personas: architect,
  CFO, DevOps engineer, requirements engineer, test engineer, UI/UX
  designer, and project manager. Evidence: cost log (`/mnt/project-files/costs/cost-log.md`)
  rows for #4, #6, #8, and board `[cost]` notes.
- **Process rules changed faster than the files that restate them.**
  About 30 to 40 PRs (#52 to #94) reshaped the team in two days. The
  follow-up rule alone changed three times (#80, #88, #89), and #86 after
  #80 and #89 after #88 revised the PR just before. Reviews of #86, #88,
  #89, and #91 each found another persona's file still saying the old
  rule, and the same sentence was reworded across files in turn. The
  folder moves in #61 to #70 then needed #85 to fix links across the
  docs. Raised by eight personas: all but the DevOps engineer.
- **Process work crowded out the product and security work.** There is no
  Phase 1 code yet, the test plan's
  [results log](/docs/canvas-portal/05-test-plan.md#7-results-log) is
  empty, and the security go-live issues
  [#16](https://github.com/bbranton/TestProj/issues/16),
  [#17](https://github.com/bbranton/TestProj/issues/17), and
  [#46](https://github.com/bbranton/TestProj/issues/46) haven't moved.
  Raised by the developer, cybersecurity engineer, and test engineer.
- **Process PRs pull in reviewers for a sentence.** The test engineer
  reviewed #88, #89, and #91 for one sentence or link each, and #91 needed
  no change. #88 had four persona reviewers. Raised by the test engineer,
  with the developer noting that a Phase 1 code PR touching sign-in will
  need at least four threads.
- **The cost record has gaps and is behind.** About nine rows say `n/a`
  because the session returned no usage numbers, seven of them from one
  reused project manager thread, so about a tenth of the log can't be
  used for estimates. Fresh threads hit it too: most of this retro's
  feedback threads have `n/a` in their `[cost]` notes on the board. No
  rows have been committed since 2026-10-26, so 43 notes ($70.03 with
  numbers) sit only on the board.
  Raised by the CFO, DevOps engineer, test engineer, project manager, and
  developer.
- **One shared GitHub account mixes reviews.** On
  [#4](https://github.com/bbranton/TestProj/pull/4), one reviewer's
  inline comments went out inside another's review, and on #94 a reviewer
  waited for another's pending review to clear. Raised by the architect
  and requirements engineer. The *Posting reviews one at a time* rule in
  the [review protocol](/team/review-protocol.md) already covers this; no
  new change was suggested.
- **Relays between doc threads were one change at a time.** Changes to
  requirements #6 reached the UI spec thread one relay at a time, so the
  same file was edited in many small rounds. Raised by the UI/UX designer
  and requirements engineer. The project manager's
  notes (`/mnt/project-files/notes/project-manager.md`) already say to send
  every owner the full list of follow-ups at once.

## Suggestions

Each suggestion is a decision request for the Team Lead. Nothing changes
until it is answered; then the owner of each file makes the change in its
own PR, citing the decision. The next retro lists those PRs here and
checks whether they helped.

1. **Fresh thread per PR, and hand off long threads.** A thread that has
   merged its PR hands follow-up work to a new one. An owner thread past
   about four Team Lead rounds or about $10 writes a hand-off note and a
   fresh thread of the same persona carries on. Suggested by the
   architect, CFO, and UI/UX designer. Changes `team/workspace.md` and the
   architect persona. Recommended. Decision request:
   [#95](https://github.com/bbranton/TestProj/issues/95).
2. **Ripple check on every process rule change.** The owner searches
   `team/`, `.claude/skills/`, `CLAUDE.md`, the PR template, and the
   glossary for the old wording, fixes every match in the same PR, and
   lists the files. Suggested by the project manager and requirements
   engineer. Changes `team/review-protocol.md`. Recommended. Decision
   request: [#96](https://github.com/bbranton/TestProj/issues/96).
3. **Keep the potential data breach rule in one place.** The review
   protocol links to the cybersecurity engineer persona instead of
   restating it. Suggested by the cybersecurity engineer. Changes
   `team/review-protocol.md` and the project manager persona.
   Recommended. Decision request:
   [#97](https://github.com/bbranton/TestProj/issues/97).
4. **Batch process changes while Phase 1 is built.** Process ideas wait on
   the board and land in one PR a week, unless one unblocks the build;
   comments from one Team Lead discussion share one PR. Suggested by the
   developer and project manager. Changes `team/review-protocol.md` and
   `team/workspace.md`. Recommended until Phase 1 is done. Decision
   request: [#98](https://github.com/bbranton/TestProj/issues/98).
5. **Notify, not review, for wording-only changes in a persona file.** The
   security "always" rule stays. Suggested by the test engineer. Changes
   `team/review-protocol.md`, and maybe a clause in `CLAUDE.md`.
   Recommended. Decision request:
   [#99](https://github.com/bbranton/TestProj/issues/99).
6. **A docs check in CI** for broken repo links and undefined FR and NFR
   IDs. Suggested by the DevOps engineer. Adds
   `.github/workflows/docs-check.yml` and a script in
   `team/Development/scripts/`. Recommended. Decision request:
   [#100](https://github.com/bbranton/TestProj/issues/100).
7. **A daily CFO batch thread**, started by the coordinator when the board
   has `[cost]` notes. Suggested by the CFO. Changes `team/workspace.md`
   and the CFO persona. Recommended. Decision request:
   [#102](https://github.com/bbranton/TestProj/issues/102).
